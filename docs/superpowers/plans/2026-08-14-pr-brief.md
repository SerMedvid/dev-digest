# PR Why + Risk Brief — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: `superpowers:executing-plans`.
> Steps use checkbox (`- [ ]`) syntax for tracking.
> `superpowers:subagent-driven-development` is **not** used in this repository —
> see the Superpowers section of the root [`CLAUDE.md`](../../../CLAUDE.md).

**Goal:** Compose a pull request's intent, blast map, diff stats, linked issue,
referenced specifications and its latest review's findings into one grounded
`Brief`, cached per `head_sha`, and render it at the top of the PR overview.

**Architecture:** A new `server/src/modules/brief/` module in the house shape —
`routes` → `service` → ports declared in the core and implemented outward, one
structured model call isolated in `model.ts`, pure transforms in `helpers.ts`,
`repository.ts` the only file touching `pr_brief`. Everything the model returns
passes a code-level grounding gate before it is persisted. The client renders it
as a `PR BRIEF` section wrapping the existing `VerdictBanner`, a `RISK AREAS`
block inside `IntentCard`, and a `Review focus` section.

**Tech Stack:** Fastify + Drizzle + Zod on `server/` (pnpm), Next 15 + React 19 +
TanStack Query on `client/` (pnpm), vitest everywhere, testcontainers for
`*.it.test.ts`.

**Spec:** [`docs/superpowers/specs/2026-08-14-pr-brief-design.md`](../specs/2026-08-14-pr-brief-design.md)

### Plan conventions (caller's standing preferences)

These override the `writing-plans` template and are deliberate:

- **Tests come after the whole implementation, not per task.** Tasks 1–10 write
  implementation only and are verified with `typecheck` alone, which is cheap.
  Every test file and every suite run — including `arch:check` — lives in Tasks
  11–13, after the last implementation task. Each implementation task still
  names, under **Test coverage owed**, exactly what Tasks 11–12 must assert for
  it, so nothing is lost by deferring.
- **Tasks state contracts, not transcribable code.** Steps name exact files,
  exact signatures and exact assertions. They do not paste implementation bodies
  for the executor to copy.
- **No task commits.** No agent in this repository commits, pushes or branches.
  Each task ends at its verification command; the caller commits.

## Global Constraints

- **Package managers differ per package.** `server/`, `client/`, `mcp/` → `pnpm`.
  `reviewer-core/`, `e2e/` → `npm`. Using the wrong one writes a second lockfile.
- **`@devdigest/shared` is two physical copies.** Every contract edit lands in
  **both** `server/src/vendor/shared/` and `client/src/vendor/shared/`, and both
  packages are type-checked.
- **`pnpm arch:check` must report exactly 24 known violations.** Never regenerate
  `.dependency-cruiser-known-violations.json` to silence a failure. It runs in
  Task 13, not per task.
- **A module never imports another module's `repository.ts`.** Cross-aggregate
  reads arrive as port objects built inline in
  [`platform/container.ts`](../../../server/src/platform/container.ts).
- **Migrations are never applied on boot** and an applied migration is never
  hand-edited. Change `src/db/schema/*.ts`, run `pnpm db:generate`, commit the
  generated SQL.
- **Every route calls `getContext(container, req)`** and scopes by `workspaceId`.
  A PR in another workspace is a **404, never a 403**.
- **`*.it.test.ts` = DB-backed** (testcontainers, self-skips without Docker).
  Anything importing `test/helpers/pg.ts` must carry that suffix.
- **Budget unit:** `est_tokens = ceil(chars / 4)`, ceiling
  `MAX_EST_TOKENS_IN = 8000` ⇒ 32 000 characters of assembled prompt.
- **No diff hunk bodies reach any prompt**, at any cap. `pr_files.patch` is never
  read on this feature's path.
- **Paths are built with `path.join` / `path.resolve`**; repo-relative paths are
  normalised to POSIX before comparison.

  findingRanges: Map<string, { start: number; end: number }[]>;
}
export function buildAllowed(input: {
  files: BriefFileRow[];
  blast: { downstream: { callers: { file: string }[];
                         endpoints_affected: string[];
                         crons_affected: string[] }[] } | null;
  specPaths: string[];
  findings: BriefFindingRow[];
}): AllowedRefs;

export interface GroundDrop { kind: 'risk' | 'ref' | 'focus' | 'line'; value: string; reason: string }
export function groundBrief(
  out: BriefOutputShape,
  allowed: AllowedRefs,
): { brief: Brief; dropped: GroundDrop[] };
```

- [ ] **Step 1: Implement `buildAllowed`**

`files` = every `pr_files` path, plus every `downstream[].callers[].file` in the
blast map, plus every specification document path actually read. `endpoints` =
every `endpoints_affected` and `crons_affected` entry. All paths normalised to
POSIX and compared **exactly** — never by `includes` or suffix, which would let
`config.ts` match `vendor/config.ts`. `findingRanges` groups findings by file.

- [ ] **Step 2: Implement `groundBrief` — the five rules**

1. Normalise each `risk.refs[]` entry; where it has the `file:line` form, split on
   the **last** `:` and match the file part. An entry in neither `files` nor
   `endpoints` is dropped from the risk (`kind: 'ref'`).
2. A risk left with zero refs is dropped entirely (`kind: 'risk'`).
3. A `review_focus` item whose `file` is not in `allowed.files` is dropped
   (`kind: 'focus'`).
4. A `review_focus` item's `line` survives only inside some
   `findingRanges.get(file)` range; otherwise it becomes `null` and the item is
   kept (`kind: 'line'`).
5. `risk_level`, `what` and `why` pass through untouched — judgements, not
   references.

Every drop carries a human-readable reason. The function is pure: it returns
`dropped`, it does not log.

```
