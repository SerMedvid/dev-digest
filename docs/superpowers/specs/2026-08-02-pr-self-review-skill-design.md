# Design — `pr-self-review` skill

Date: 2026-08-02
Status: approved, not yet implemented

## Problem

The repo has twelve skills in [`.claude/skills/`](../../../.claude/skills/) and a
set of hard invariants spread across [`CLAUDE.md`](../../../CLAUDE.md), the
per-package `CLAUDE.md` files, and `INSIGHTS.md`. Whether any of that reaches a
change before it becomes a pull request is currently a matter of whether the
agent happened to load the right skill while writing the code.

Three concrete gaps:

1. **Skills are loaded by topic, not by diff.** An agent editing
   `client/src/app/**` may or may not have `next-best-practices` in context. By
   the time the PR is open, nobody re-checks.
2. **Nothing looks at the change as a whole.** Each skill governs the code being
   written at that moment. No pass asks "given everything this branch touches,
   which rules apply and are they all satisfied?"
3. **The cheap checks are the ones most often skipped.** `pnpm typecheck`,
   `pnpm arch:check`, and the hermetic test lane take seconds and catch the most
   common breakage, but they are run ad hoc.

The result is that review pressure lands on the human reviewer for things a
machine already knows how to check.

## Goal

A skill that reviews the branch diff before the PR exists, routes each changed
file to the skills that govern it, and refuses to let a pull request open while
a critical finding stands — with an override that is possible, recorded, and
uncomfortable enough not to be reflexive.

## Decisions

| Question | Decision |
|---|---|
| Enforcement | Skill **plus** a `PreToolUse` hook. The hook does not run the review; it denies `gh pr create` and tells the agent to run the skill. |
| Diff scope | Committed only: `git merge-base main HEAD` → `HEAD`. Uncommitted work is out of scope, but its presence is recorded. |
| Skill routing | A static `routing.md` manifest (glob → lanes) inside the skill. No runtime inference, no edits to vendored skills. |
| Severity | A **closed list of blockers** in `blockers.md`. Everything not on that list is a note and never blocks. |
| Override | Per-finding, reason required, one SHA of lifetime, written into the report and the PR draft. Phase 1 is not overridable. |
| Byproduct | A PR description draft is generated when the verdict is not `BLOCKED`. |
| CI | Out of scope. The gate is local, pre-PR. |
| Vendored skills | Not modified. [`skills-lock.json`](../../../skills-lock.json) hashes them; routing lives on our side of that boundary. |

## Entry point and trigger

The skill is user-invocable as `/pr-self-review`. Automatic invocation works
indirectly and deliberately:

```
agent runs: gh pr create ...
  → PreToolUse hook fires on Bash
  → no fresh green report for HEAD
  → deny + reason: "run /pr-self-review first"
  → agent reads the denial and invokes the skill
```

The hook is a gate, not a scheduler. It never spawns a review itself, so there
is one code path for automatic and manual runs, and the review always happens in
the session the user can see.

**Gated commands.** By default `gh pr create` and `gh pr ready`. Setting
`DEVDIGEST_GATE_PUSH=1` extends the matcher to `git push`.

**Known gap:** opening a PR through the GitHub web UI bypasses the hook
entirely. `DEVDIGEST_GATE_PUSH=1` narrows this to "pushed before, opened later";
nothing closes it fully without CI, which is out of scope.

## Pipeline

### Phase 0 — Collect the diff

```
BASE=$(git merge-base main HEAD)      # origin/main if it resolves, else main
git diff --name-status $BASE..HEAD
```

Stop conditions, each with a specific message:

- current branch is `main` → nothing to review
- `HEAD` has no commits ahead of `BASE` → nothing to review
- neither `origin/main` nor `main` resolves → stop and say so; do not guess a base

Excluded from review but listed in the report: lock files, `**/migrations/*.sql`
(generated by `pnpm db:generate`), `*.snap`, `agent-runner/dist/**`.

A dirty working tree does not stop the run — the scope is committed code — but
`dirty: true` is recorded in the report and printed as a warning, because what
the user is looking at locally is not what was reviewed.

### Phase 1 — Deterministic gate, no tokens

Packages are derived from the changed paths. Commands are the real ones from
each `package.json`; note that the package manager differs per package.

| Touched | Commands |
|---|---|
| `server/**` | `pnpm typecheck` · `pnpm arch:check` · `pnpm exec vitest run --exclude '**/*.it.test.ts'` |
| `reviewer-core/**` | `npm run typecheck` · `npm test` · **and** `server`: `pnpm typecheck` |
| `client/**` | `pnpm typecheck` · `pnpm test` |
| `e2e/**` | `npm run typecheck` only |
| `server/src/vendor/shared/**` or `client/src/vendor/shared/**` | typecheck **both** `server` and `client` |

The `reviewer-core` row is not redundant: `server` type-checks against
`../reviewer-core/src` through a path alias, so a change there can only break
`server`.

Any non-zero exit → one `CRITICAL` finding carrying the command and the last 30
lines of output, verdict `BLOCKED`, pipeline stops. No LLM lane runs. This is
the common case and it costs nothing.

`arch:check` needs `server/.dependency-cruiser-known-violations.json` to exist.
If it is missing the command fails with `Can't open … for reading`; the skill
recognises that specific string and reports "run `pnpm arch:baseline`" instead
of presenting it as an architecture violation.

### Phase 2 — Route files to lanes

`routing.md` maps globs to lanes. A **lane** is a triple: one skill, one bucket
of changed files, and the mandatory context for that bucket.

| Glob | Lanes |
|---|---|
| `server/src/**/routes.ts`, `server/src/app.ts` | fastify-best-practices · onion-architecture · security · zod |
| `server/src/**/repository*.ts`, `server/src/db/**` | drizzle-orm-patterns · onion-architecture |
| `server/src/db/schema/**` | postgresql-table-design · drizzle-orm-patterns |
| `server/src/{modules,adapters,platform}/**` | onion-architecture · typescript-expert |
| `client/src/app/**` | next-best-practices · frontend-architecture |
| `client/src/**/*.tsx` | react-best-practices · frontend-architecture |
| `client/**/*.test.tsx` | react-testing-library |
| `**/vendor/shared/**` | zod · typescript-expert |

A file may land in several lanes; that is the point. A lane with an empty bucket
is not dispatched.

**Mandatory context per lane** is the package's own `CLAUDE.md` and
`INSIGHTS.md`. Without them a reviewer subagent does not know that
`@devdigest/shared` is two physical copies, that a query without `workspaceId`
is a bug, or that `reviewer-core` accepts prompt slots nothing feeds yet.

A changed file that reaches no lane lands in exactly one of three buckets, named
separately in the report:

- **Excluded** — generated or opaque: lock files, `**/migrations/*.sql`,
  `*.snap`, `agent-runner/dist/**`.
- **Not routed by design** — real files this skill has no opinion on:
  `**/*.md`, `docs/**`, `.claude/**`, `.github/**`, `scripts/**`.
- **Unrouted** — everything else. This is the manifest's rot detector, so it
  must normally be empty: a `.ts` file appearing here means a new directory
  exists and `routing.md` needs a row. Without the middle bucket, every doc-only
  PR would fill this list and the signal would be gone.

None of the three gets a general-purpose review pass, and none produces
findings.

### Phase 3 — Parallel review lanes

One subagent per lane, dispatched via `superpowers:dispatching-parallel-agents`,
at most six concurrent. Each subagent receives its skill, its bucket's diff
hunks, the mandatory context, `blockers.md`, and an output contract.

Three rules bind every lane:

1. Report only on lines present in the diff. Pre-existing problems in untouched
   parts of a changed file are out of scope.
2. Every finding cites `path:line` and quotes the line verbatim.
3. Severity comes from `blockers.md` and nowhere else. A lane may not invent a
   critical category, and the severity labels inside `react-best-practices` do
   not carry over.

A lane that fails, times out, or returns unparseable output yields a single
`CRITICAL` finding with category `lane-failed`. Blocking on an infrastructure
failure is annoying; silently passing because a reviewer crashed is worse. This
one is overridable.

### Phase 4 — Merge, ground, decide

**Grounding gate.** A finding whose cited line is not in the diff is discarded,
not downgraded. This mirrors the grounding gate the product's own review
pipeline already applies in `reviewer-core`, and it is what keeps a hallucinated
`CRITICAL` from blocking a correct PR.

**Dedupe** on `(path, line, category)`; when two lanes agree, keep the higher
severity and record both skills.

**IDs** are assigned after sorting by severity, then path, then line:
`CRIT-1`, `CRIT-2`, `HIGH-1`, `MED-1`. Sorting is what makes an ID stable enough
to name in an override.

**Verdict:** `BLOCKED` if any `CRITICAL` survives, otherwise `PASS`.

**Artifacts:**

- `.devdigest/pr-self-review/<head-sha>.md` — the human report
- `.devdigest/pr-self-review/latest.json` — what the hook reads

```json
{
  "head": "9e81b60…",
  "base": "5a21cc5…",
  "verdict": "BLOCKED",
  "dirty": false,
  "counts": { "critical": 2, "high": 4, "medium": 7 },
  "critical": [{ "id": "CRIT-1", "path": "server/src/…", "line": 42, "summary": "…" }],
  "overrides": [],
  "report": ".devdigest/pr-self-review/9e81b60….md"
}
```

`.devdigest/pr-self-review/` is added to `.gitignore`. (`.devdigest/cache/` is
already ignored; the reports are not cache and get their own line.)

**Console block**, fixed shape so it is greppable and quotable:

```
PR-SELF-REVIEW: BLOCKED
base 5a21cc5 → head 9e81b60
critical 2 · high 4 · medium 7
report .devdigest/pr-self-review/9e81b60.md
```

### Phase 5 — PR description draft

Runs only when the verdict is not `BLOCKED`. Appended to the report as a
copy-paste block:

- title in conventional-commit form with a scope, derived from the touched packages
- what changed and why, from the commit bodies and the diff
- risk notes
- test plan: the Phase 1 commands that passed, plus what needs manual checking
- touched packages → which workflows in `.github/workflows/` their path filters
  will trigger
- surviving non-critical findings, as a checklist for the reviewer
- the override block, if any (see below)

## Override

Invoked as a second step, after a `BLOCKED` verdict has been printed and the
findings have been read — never as a flag on the initial run:

```
/pr-self-review --override CRIT-1,CRIT-3 --reason "<text>"
```

Rules:

- **Per finding.** IDs are required. There is no `--override all`.
- **Reason required.** Rejected: empty, and the literal set
  `wip`, `later`, `ok`, `fix soon`, `n/a`, `-`. A reason shorter than 15
  characters is rejected.
- **Phase 1 is never overridable.** A red typecheck, a red `arch:check`, or a
  failing hermetic test is not a judgement call.
- **One SHA of lifetime.** A new commit invalidates the report, and the override
  goes with it. If the blocker is real it comes back and the reason gets written
  again.

Recorded in three places: `overrides[]` in `latest.json`, a section at the top
of the report, and a `⚠️ Self-review overridden` block in the PR draft naming
each finding, its file, and the reason. The reviewer sees it first, not never.

## The hook

`.claude/settings.json` gains a `PreToolUse` entry matching `Bash`, running
`node "$CLAUDE_PROJECT_DIR/scripts/pr-self-review-gate.mjs"`. Node, not shell:
`scripts/*.sh` are POSIX and this must work on Windows too.

The script reads the hook payload from stdin and:

1. Extracts `tool_input.command`. If it does not match `gh pr create` /
   `gh pr ready` (or `git push` when `DEVDIGEST_GATE_PUSH=1`), allow and exit.
2. Reads `latest.json`. Missing → deny: "run `/pr-self-review` first".
3. Compares `latest.json.head` with `git rev-parse HEAD`. Different → deny:
   "report is stale, re-run `/pr-self-review`".
4. `verdict === "BLOCKED"` → deny unless every critical finding ID appears in
   `overrides[]`. The denial lists the IDs still outstanding.
5. Otherwise allow.

Command matching normalises whitespace and searches the whole string, so a
`&&` chain or a leading env assignment still matches. The match is deliberately
over-broad — the word `gh pr create` inside a quoted string will trigger it. A
false block costs one review run; a missed one defeats the gate.

`base` drift is informational only. If `main` advances after the review, the
merge-base changes but the reviewed commits do not, so the report stays valid.

## Skill package

```
.claude/skills/pr-self-review/
  SKILL.md            entry point: the five phases, the verdict format, the checklist
  routing.md          glob → lanes manifest, plus the mandatory-context rule
  blockers.md         the closed list of CRITICAL categories
  report-template.md  report and PR-draft skeletons
scripts/
  pr-self-review-gate.mjs
```

Frontmatter follows the house convention (`name`, `description`,
`allowed-tools`), user-invocable, and the skill is added to the catalog table in
[`.claude/skills/README.md`](../../../.claude/skills/README.md).

## `blockers.md` — the closed list

A finding is `CRITICAL` only if it matches one of these. Everything else is
`HIGH` or `MEDIUM` and never blocks.

1. **Phase 1 red** — typecheck, `arch:check`, or the hermetic test lane fails on
   a touched package.
2. **Secret committed** — an API key, token, password, or a `.env` file in the
   diff. Secrets belong in `~/.devdigest/secrets.json`, outside the repo.
3. **Confirmed vulnerability with attacker-controlled input** — only the
   HIGH-confidence tier of the `security` skill's own rubric: the vulnerable
   pattern *and* a traced attacker-controlled source. Theoretical findings are
   notes.
4. **Missing workspace scoping** — a query or mutation against a
   workspace-scoped table with no `workspaceId` in the predicate.
5. **Irreversible destructive operation** — `docker compose down -v`, or a
   hand-edit to an already-applied migration in `server/src/db/migrations/`.
6. **Half-applied shared contract** — a change to `@devdigest/shared` written to
   one physical copy and not the other.
7. **Wrong package manager** — `package-lock.json` appearing in `server/` or
   `client/`, or `pnpm-lock.yaml` in `reviewer-core/` or `e2e/`.
8. **Portability break** — a hardcoded path separator, a
   `file://${process.argv[1]}` entrypoint check, or an absolute machine-specific
   path in application code.
9. **`lane-failed`** — a review lane crashed and its bucket went unreviewed.

## Behaviour and degradation

| Situation | Behaviour |
|---|---|
| Only excluded files changed (lock files, generated SQL) | `PASS` with a note. No lanes dispatched. |
| Diff touches no routed glob | `PASS`; every file listed under its not-reviewed bucket. |
| A lane crashes or times out | `CRITICAL` `lane-failed` for that lane; other lanes still report. Overridable. |
| `arch:check` baseline file missing | Reported as "run `pnpm arch:baseline`", not as an architecture violation. |
| Docker not running | Irrelevant — the hermetic lane excludes `*.it.test.ts`, which self-skip anyway. |
| Working tree dirty | Warning printed, `dirty: true` in the report; the run proceeds. |
| Report exists but `HEAD` moved | Hook denies as stale. |
| Hook script throws | Fails **closed**: deny with the error text. A broken gate that lets everything through is not a gate. |

## Acceptance

The work is done when all of these hold:

1. `/pr-self-review` on a branch with a clean, small diff prints a `PASS` block
   and writes both artifacts.
2. Introducing a deliberate type error in a touched package produces `BLOCKED`
   with one `CRITICAL`, and **no** review lane is dispatched.
3. `gh pr create` with no report is denied by the hook with a message naming
   `/pr-self-review`.
4. `gh pr create` after a `PASS` run is allowed.
5. Committing anything after a `PASS` run makes the next `gh pr create` deny as
   stale.
6. `--override CRIT-1 --reason "…"` on a `BLOCKED` report flips the hook to
   allow, and the override appears in `latest.json`, the report, and the PR
   draft.
7. `--override` on a Phase 1 finding is refused.
8. `--reason wip` is refused.
9. A `.ts` file under a directory in no glob appears under `unrouted`, while a
   changed `docs/**` file appears under "not routed by design".
10. A finding citing a line absent from the diff is dropped by the grounding
    gate and appears nowhere in the report.
11. The gate script runs on Windows and Linux with no shell-specific syntax.

## Out of scope

- A CI workflow duplicating the review. This is a pre-PR local gate.
- A `pre-push` git hook running headless `claude -p`. Slow, and it needs a key
  in every contributor's environment.
- Reviewing uncommitted changes.
- A persistent allowlist / baseline for legacy findings. The scope is changed
  lines only, so legacy code cannot block. Add one later if that turns out to be
  wrong, with the depcruise rule: it may only shrink.
- Editing any vendored skill or `skills-lock.json`.
- Auto-fixing findings. The skill reports; fixing is a separate decision.
